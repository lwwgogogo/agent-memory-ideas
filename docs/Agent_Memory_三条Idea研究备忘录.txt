Agent Memory 三条研究 Idea 备忘录
从 failure mode 出发：记忆更新、条件化抑制与修订惯性
研究定位
本文不是把三个方向合成统一框架。三条线分别对应长期记忆更新（Idea 1）、记忆访问/检索（Idea 2）和工作上下文/推理轨迹（Idea 3）。目前建议把 Idea 1 作为主线优先验证，Idea 2 作为备选，Idea 3 作为独立旁支。

整理日期：2026-09-24
一、总体摘要
经过前期文献查重，最初的“Volatility / Surprise / Inhibition”三个机制名都已有明显邻近工作，因此本备忘录不再以“套一个外领域机制”为出发点，而改为三个可证伪的 failure mode。核心原则是：先证明现有方法在受控条件下系统失效，再决定是否引入控制理论、贝叶斯更新、抑制机制或重规划策略。

共同方法论
三条线都遵循“Failure-first”：先构造一个简单、可控、现有方法稳定失败的场景；再提出最小机制；最后才上开放式 Agent 环境。若 oracle 条件都没有收益，或收益仅存在于显式机制标签的合成数据中，则停止主创新声称。

二、Idea 1：Noise or Change? —— 区分状态变化与观测噪声的记忆更新
2.1 现存问题
长期 Agent 会持续接收新证据并修改已有记忆。当前一个关键缺口是：当新证据与已有记忆冲突时，系统往往把 conflict、recency、surprise 或 posterior change 当作“需要更新”的信号，但相同的表面冲突可能来自两个完全不同的数据生成过程。
H_change:  x_t ≠ x_{t-1}        （真实状态发生变化）
H_noise:   x_t = x_{t-1},  y_t ≠ x_t   （状态未变，但观测有噪声）
如果把二者混为一谈，就会产生两个方向相反的错误：更新太快会对噪声过度反应（Noise Overreaction）；更新太慢又会继续使用已经过时的状态（Stale Memory Reuse）。因此问题不是“冲突有多大”，而是“冲突来自世界变化，还是证据不可靠”。
2.2 现有解决方法与边界
现有路线
已经解决了什么
仍然留下的问题
STALE / CUPMem
显式研究旧记忆被后来证据隐式失效的问题，并强调 state adjudication
重点是 stale state resolution；并未把“真实 drift”和“观测噪声”建模为两个独立不确定性源
StateMemBench / StateMem
把 superseded state tracking 单独定义为能力，并跟踪替代关系和依赖
主要回答“当前状态是谁”；对 observation reliability 的显式建模不是中心
BeliefMem
用多个 candidate conclusion + probability 保留不确定性，缓解 deterministic memory 的自强化错误
“有 uncertainty”不等于区分 uncertainty 来自 process 还是 observation
D-MEM
用 Reward Prediction Error / surprise 触发 fast-slow memory evolution
RPE 表示结果偏离预期，并不能单独区分状态变化与观测噪声
Memini
通过 fast/slow dynamics 实现多时间尺度更新与巩固
多时间尺度本身不能回答“为什么这次冲突应该快更新还是忽略”

2.3 我们的解决方法
核心命题
Memory revision should distinguish latent-state volatility from observation unreliability. 即：记忆更新不应只看冲突/惊讶程度，而应显式区分“真实状态变化率”与“证据可靠性”。

把已有 memory 看作对 latent state x_t 的估计，把新文本/工具反馈/用户陈述看作 observation y_t。我们不把 Kalman Filter 作为论文卖点，而是借它最重要的变量分解：过程噪声 Q 描述世界自身变化速度，观测噪声 R 描述证据质量。
x_t = f(x_{t-1}) + w_t,      w_t ~ Q    （process volatility）
y_t = h(x_t) + v_t,          v_t ~ R    （observation uncertainty）
第一版方法可以非常简单：维护 state belief + uncertainty；新 evidence 到来后，先计算与预测的 innovation，再根据 uncertainty 做归一化；如果 mismatch 可由观测噪声解释，则保持/验证旧 memory；如果 mismatch 持续且更符合 state drift，则提高更新速率或触发状态替代。
2.4 解决原理
（1）Innovation：检测“预测与观测是否不一致”。
ν_t = y_t - ŷ_t
（2）Uncertainty normalization：raw conflict 为 10 并不说明异常程度相同。如果系统本来就高度不确定，差 10 可能正常；如果不确定性极低，差 10 可能是强异常。可借 Normalized Innovation Squared（NIS）的思想：
S_t = H P_t^- H^T + R_t
NIS_t = ν_t^T S_t^{-1} ν_t
（3）Q/R 分离：Innovation 负责发现 mismatch；Q/R 负责解释 mismatch。Q 高表示状态本来变化快，应更愿意相信新证据；R 高表示观测本来不可靠，应降低新证据对长期 memory 的影响。
Q ↑  ⇒  update rate ↑       ;       R ↑  ⇒  update rate ↓
（4）必要时引入 change-point：如果 normalized mismatch 连续出现，可以把“旧状态被覆盖”升级为“进入新 regime”，从而保存历史状态而不是把所有版本粗暴 merge。
2.5 验证方法
第一阶段只验证问题是否成立，不需要 LLM。构造二元 latent state：x_t∈{0,1}，并人工控制真实状态变化概率 Q 与观测翻转概率 R。

推荐 Baseline：Last observation、Majority history、Fixed EMA/decay、Recency-weighted、Raw conflict/surprise、简单 Bayesian belief update。必须加入 Oracle-Q/R：直接提供真实 Q、R，先测“如果能正确区分 noise/change，理论收益是否足够大”。

第二阶段再在线估计 Q/R（简单 HMM / Bayesian filtering）；第三阶段加入 NIS gate；第四阶段迁移到自然语言 synthetic，再进入 STALE / StateMemBench 等 evolving-state benchmark。
2.6 可证伪条件
如果 Oracle-Q/R 在匹配信息量后仍不能明显优于简单 recency/EMA，则停止。
如果简单 LLM prompt“判断这是环境变化还是偶发噪声”已达到同等效果，复杂 filtering 不值得做。
如果收益只在显式提供 Q/R 标签的 synthetic 环境存在，而自然语言冲突或真实 benchmark 中消失，则收缩为分析工作，不包装成通用 memory updater。
三、Idea 2：Outcome-conditioned Contextual Inhibition —— 基于有害后果的条件化记忆抑制
3.1 现存问题
Memory retrieval 常使用语义相似度、Top-K、intent compatibility 或全局 utility。一个更细的问题是：同一条 memory 可能在 context A 中有帮助，在 context B 中有害。此时全局删除、全局降权或固定 forgetting 都会损失其在其他场景中的价值。
Δ(m, q_A) > 0      但      Δ(m, q_B) < 0
因此真正需要证明的 failure mode 是“contextual utility sign-flip”：一条记忆的效用不是全局常数，而是条件化的。如果这个现象不存在，那么所谓 inhibition 很可能只是给 contextual utility 换名字。
3.2 现有解决方法与边界
现有路线
已经解决了什么
与本 Idea 的区别
STITCH (ACL 2026)
用 latent goal、action type、entity type 等 contextual intent 过滤并压制语义相似但 context 不匹配的历史
主要是基于当前 intent 的兼容性过滤，不是根据过去“实际产生的有害结果”学习抑制轨迹
Human-Inspired Memory Architecture
包含 interference-based forgetting、consolidation、reconsolidation 等机制
更偏全局 memory maintenance / pruning，并不等价于“在某个 context 下抑制、其他 context 保留”
FSFM
系统讨论 passive decay、active deletion、safety-triggered、adaptive reinforcement 等 selective forgetting
重点仍是 forgetting/retention；条件化负效用的 sign-flip 不是其核心问题
Experience-Following (ACL 2026)
发现高相似 experience 会强烈引导输出，并造成 error propagation / misaligned replay
给出了 failure motivation，但没有把有害影响转成 context-specific inhibitory trace

3.3 我们的解决方法
核心命题
不要把“某条 memory 在一次任务中有害”直接等价为“这条 memory 全局有害”。只有在可归因的 context 下形成负反馈；在其他 context 中仍允许正常检索。

首先沿用 Failure-Grounded Utility 的干预思想，估计某条 memory 在当前 context 下的增量效用：
Δ(m,q) = Success(q | m retrieved) - Success(q | m blocked)
如果 Δ(m,q)<0，不做 global delete，而学习一个 context-conditioned inhibitory trace h(m,c)。下一次在相似 context c 中，检索分数减去抑制项；在其他 context 中，memory 保持可用。
score_eff(m,q,c) = score_base(m,q) - λ · h(m,c)
h_{t+1}(m,c) = ρ h_t(m,c) + η · 1[attributed harmful effect]
3.4 解决原理
该思路借鉴但不声称复现认知神经机制。认知科学中的 Retrieval-Induced Forgetting（RIF）说明检索一个目标时，竞争项可能被抑制；Nonmonotonic Plasticity Hypothesis（NMPH）进一步提出：低激活近似不学习，中等激活可能导致 weakening，高激活导致 strengthening。对 Agent 的可操作启发是：retrieval/activation 不应单调等价于强化。
activation low → no change ; moderate → weaken ; high → strengthen
我们不直接照搬 U-shaped rule，而把重点放在“outcome-conditioned negative plasticity”：只有当某条被激活/检索的 memory 经因果或近似归因被判定为当前 context 下有害时，才形成可衰减的条件化抑制。
3.5 验证方法
第一步不是实现 inhibition，而是先证明 contextual sign-flip 确实存在。构造同一 memory 在不同 context 中分别 helpful / harmful 的任务对；例如同一策略在“信息检索任务”中有益、在“需要新证据覆盖旧经验”的任务中误导。
建议对照组：Semantic Top-K、STITCH-like intent filtering、Global utility reweighting、Global delete/downweight、Contextual utility without inhibition、Proposed inhibitory trace。
指标：Task success、Harmful Memory Reuse Rate、Useful Memory Retention Rate、Contextual Sign-flip Recovery、False Suppression Rate，以及抑制在 context 切换后的恢复速度。
关键消融：去掉 outcome attribution，只按 semantic mismatch 抑制；去掉 context，仅全局降权；去掉 decay，观察抑制是否永久污染。
3.6 可证伪条件
如果同一 memory 的效用很少出现正负翻转，global utility 已足够，则不需要 inhibition。
如果 STITCH-like intent filtering 已能消除绝大多数 harmful replay，且 outcome-conditioned trace 无额外收益，则停止。
如果 proposed inhibition 最终数学上等价于一个普通 contextual utility score，没有不同的动力学或可验证行为，则不要包装成新机制。
四、Idea 3：Revision Inertia —— 什么时候应局部修订，什么时候应重规划/重置？
4.1 现存问题
真实使用中常见一个现象：第一次输出不满意后，即使用户明确指出问题，Agent 的第二版仍与原方案高度相似，更多是措辞调整、局部补丁，而不是重新理解任务和搜索新的解空间。这个问题发生在 working context / trajectory，而不是 long-term memory。
2025 年的 LLMs Get Lost in Multi-Turn Conversation 已发现：模型在信息逐步给出时常过早形成假设并生成答案，随后过度依赖早期错误尝试，出现“走错后难以恢复”。ACL 2026 的 Breaking Contextual Inertia 更直接指出，即使后续有明确纠正，模型仍可能坚持原 reasoning trace。
4.2 现有解决方法与边界
现有路线
已经解决了什么
仍可切入的点
LLMs Get Lost in Multi-Turn Conversation
系统证明 multi-turn underspecification + premature answering 会造成 unreliability 和恢复困难
主要研究逐步补充信息；“完整初稿被明确否定后如何选择 refine/replan/reset”不是唯一中心
Breaking Contextual Inertia / RLSTA
用 single-turn anchors 作为奖励信号训练模型打破旧 reasoning trace
偏训练方法；测试时 Agent 如何根据 feedback 类型动态选择 revision mode 仍可研究
AgentSwing
在工作上下文过长时动态选择 Keep Last N / Summary / Discard，并短期前瞻选择分支
动作针对 context compression；没有专门针对“用户否定旧方案后的 revision mode”
一般 self-refinement / self-correction
让同一个模型 critique → revise
Generator 与 Critic 共享偏差和旧上下文，容易在原解附近修补

4.3 我们的解决方法
核心命题
Revision ≠ Replanning。Agent 不应把所有用户反馈都映射成“修改上一版”，而应根据 feedback 对旧 trajectory 的失效程度，在 Local Refine / Partial Replan / Full Reset / Alternative Branch 之间做选择。

把每次用户反馈看作对当前 trajectory 的证据。如果反馈只否定局部属性，保留大部分历史是合理的；如果反馈否定核心目标、结构、假设或方案方向，则应把它视作 trajectory change-point，显式降低旧答案和旧 reasoning trace 在下一轮中的条件影响。
a_t ∈ {Refine, Partial-Replan, Full-Reset, Alternative-Branch}
这里不必一开始训练模型。测试时可以先做一个轻量 revision controller：根据 feedback 的 scope、severity、constraint novelty、是否显式否定核心假设等信号，选择不同的 context transformation。
4.4 解决原理
可借鉴两个数学/系统思想。第一是 path dependence / hysteresis：当最终有效信息相同，如果“先生成错误答案再修订”与“直接看到完整需求”产生系统差距，说明历史路径本身在影响输出。第二是 change-point / model reset：当反馈表明旧 trajectory 的生成模型已失效，不应继续做小幅参数修补，而应切换 regime 或重启规划。
G_rev = Score(y_fresh) - Score(y_revision)
AnchorRatio = Sim(y_revision, y_0) / Sim(y_fresh, y_0)
其中 y_0 是第一版，y_revision 是带旧答案历史后的修订，y_fresh 是把当前所有有效约束一次性重述给一个 fresh context 后的输出。若 Revision Gap 持续为正，且 AnchorRatio 显著大于 1，就能量化“旧答案锚定”。
4.5 验证方法
最干净的实验设计是“信息等价、路径不同”。构造最终有效任务 Q*，然后比较三种条件：
Fresh：直接把 Q* 一次性给模型，得到 y_fresh。
Revision：先给不完整/可误导的 Q0 得到 y0，再给 correction c（满足 Q0+c 等价于 Q*），保留旧答案和旧 trajectory，得到 y_revision。
Reset：同样先经历 Q0→y0，但收到 correction 后清除/摘要失效 trajectory，仅给当前有效约束 Q*，得到 y_reset。
如果 Score(y_reset) 显著高于 Score(y_revision)，而二者当前有效信息相同，就说明旧 trajectory 本身造成负迁移。
进一步把 feedback 分层：Surface（措辞/长度）、Local structural（局部布局/局部逻辑）、Global structural（整体组织）、Goal invalidation（核心理解/目标错误）。测试 optimal action 是否随 feedback severity 改变。
Baseline：直接 revise、critique-then-revise、fresh restart、fixed reset、AgentSwing-like branch、rule-based revision controller。指标：Revision Gap、First-pass→Second-pass Quality Gain、Output Diversity / distance、Constraint Satisfaction、Token Cost、以及“过度重置导致丢失有效线索”的成本。
4.6 可证伪条件
如果 fresh/revision/reset 三者在信息匹配后差异很小，则 revision inertia 不够强。
如果简单“重新陈述完整需求 + 不展示旧答案”就完全解决问题，则贡献更适合作为 context-management heuristic，而不是复杂 controller。
如果 revision mode classifier 的收益只来自多花 token / 多采样分支，则需要严格成本匹配，否则不能声称策略更好。
五、三条 Idea 的关系与建议验证顺序
三个方向不建议合并成统一系统。它们作用在不同层：Idea 1 决定“记忆内容是否应更新”；Idea 2 决定“已有记忆是否应在当前 context 被激活”；Idea 3 决定“当前 episode 的旧轨迹是否应继续沿用”。唯一共享的是方法论：都把“历史信息不是天然有益”作为出发点。
